핵심 요약
  • 프로그램은 이용자 본인의 컴퓨터에서 실행됩니다.
  • 치지직 로그인 정보, 시청자 출석 기록과 출석부 기록, 설정 등은 이용자 컴퓨터에만 저장됩니다. 시청자 출석 기록·출석부 기록과 설정은 외부로 전송되지 않습니다.
  • 2.3부터 치지직 로그인과 하루 한 번의 로그인 갱신은 운영자 서버를 거쳐 치지직과 주고받습니다. 서버는 이를 저장하거나 기록하지 않습니다. (직접 발급한 API 키로 쓰는 경우는 거치지 않습니다.)
  • 그 밖에 운영자 서버로 전송되는 것은 이용권 확인에 필요한 최소한의 정보(치지직 채널 식별자, 치지직 로그인 정보(채널 확인용), 연장 코드 또는 주문번호), 새 버전 확인 요청, 공용 연결 확인 요청, 그리고 끌 수 있는 진단 정보와 최초 실행 신호입니다.
  • 스마트스토어에서 이용권을 사면 네이버가 판매자인 운영자에게 구매자 이름·연락처·배송지를 넘깁니다. 운영자는 결제 확인·발송 처리·환불과 문의 처리에만 쓰며, 운영자의 서버에는 저장하지 않습니다(4항).

  • 치지직 로그인과 로그인 갱신 시 (2.3부터, 키 없이 로그인만 하는 방식): 치지직이 로그인 뒤 돌려주는 인증 코드와, 하루 한 번 로그인을 갱신할 때의 갱신 토큰. 치지직이 앱마다 주는 비밀 키(Client Secret)를 프로그램 안에 넣어 둘 수 없어, 운영자 서버가 그 키를 붙여 치지직에 대신 요청하고 받은 로그인 정보(액세스·리프레시 토큰)를 그대로 프로그램에 돌려줍니다. 운영자 서버는 이 값들을 저장하지도 기록하지도 않으며, 로그인 정보는 이용자 컴퓨터에만 남습니다. 채팅을 읽고 쓰는 등 그 밖의 통신은 이용자 컴퓨터와 치지직 사이에서 바로 이루어집니다. 직접 발급한 API 키로 쓰는 경우에는 이 전송이 없습니다.
  • 공용 연결 확인 시 (키 없이 로그인만 하는 방식): 로그인할 때, 그리고 2.6.2부터는 봇을 켤 때와 켜 둔 동안(한 시간에 한 번, 다시 로그인한 것을 알아챘을 때), 설정 창·초기 설정 창을 열 때 지금 쓰는 공용 앱 정보(앱 ID, 로그인 뒤 돌아올 주소, 봇 답에 붙는 이름, 2.6.3부터 봇 답을 보내는 운영자 봇 계정의 채널 식별자)를 묻습니다. 운영자가 등록한 앱이 바뀌었을 때 다시 로그인하라고 알리고, 봇 계정 없이 보낸 답이 어떤 이름으로 나가는지 보여 주고, 채팅으로 다시 들어온 봇 답을 시청자 채팅과 구분하기 위한 것입니다. 요청에 개인을 식별하는 정보는 포함되지 않습니다. 직접 발급한 API 키로 쓰는 경우에는 묻지 않습니다.
  • 연장 코드 등록 시: 입력한 연장 코드와 그 채널의 치지직 채널 식별자. 코드의 정당성과 최초 사용 여부를 확인하고 그 채널의 이용 기간에 더하기 위함입니다.
  • 주문번호 등록 시: 입력한 스마트스토어 주문번호와 그 채널의 치지직 채널 식별자. 결제 완료 여부를 확인하고 그 채널의 이용 기간에 더하기 위함입니다. 운영자 서버는 주문 확인 서버(한국 서울 — 7항)를 거쳐 네이버 커머스에 결제 상태를 묻습니다. 주문 확인 서버가 답한 때 찾지 못한 번호(잘못 넣은 휴대폰 번호 등)는 남기지 않습니다(같은 주문이 두 번 반영되지 않게 잠깐 거는 잠금 표시만, 번호를 그대로 적지 않고 해시값으로 잠시 남을 수 있습니다 — 5항). 주문 확인 서버가 잠시 답하지 않으면 주문번호 꼴(16자리이고 앞 8자리가 최근 날짜)인 번호를 받아 두었다가 확인되는 대로 반영합니다(5항).
  • 버전 확인 시: 새 버전 여부를 확인하기 위한 요청. 개인을 식별하는 정보는 포함되지 않습니다.
  • 이용권 동기화 시: 치지직 채널 식별자. 프로그램을 재설치해도 무료 체험 기간과 구매한 이용권이 그대로 이어지도록 하기 위한 것입니다(운영자가 이 기록을 쓰는 곳은 5항). 2.9.0부터는 봇을 켤 때 치지직 로그인 정보(액세스 토큰)도 함께 보내, 운영자 서버가 치지직에 "이 로그인의 채널"을 물어 보낸 채널과 같은지 확인합니다. 이때 채널의 주인으로 확인되어야 체험 기록을 새로 만들거나 그 시작 때를 앞당기고 진단 정보 확인 표(아래)도 내주며, 운영자 서버는 이 로그인 정보를 저장하지도 기록하지도 않습니다. 직접 발급한 API 키로 쓰는 경우에도 이용권 동기화 때는 이 로그인 정보가 함께 갑니다(로그인·갱신 때 운영자 서버를 거치지 않는 것과는 다릅니다). 이 요청에 최초 실행 신호(아래)의 설치 식별자가 함께 와도 운영자 서버는 쓰지 않고 버립니다.
  • 진단 정보 전송 시 (1.7.1부터): 프로그램 버전, 봇의 시작·연결 상태, 오류 메시지, 치지직 안내 이벤트의 종류 번호와 닉네임을 가린 안내문, 명령어·기능 종류별 사용 횟수(투표·추첨·룰렛·TITS·알림 카드 종류·알림 소리·TTS, OBS에 넣은 오버레이의 종류 등), 후원 금액 구간, 치지직 채널 식별자, 봇을 끌 때 켜 둔 시간과 끈 까닭(직접 끔·컴퓨터 종료·자동 업데이트, 2.2부터. 다시 로그인, 2.6.2부터). 2.6.2부터는 치지직 로그인이 풀렸는지(봇을 켤 때인지 켜 둔 동안인지와 오류 번호), 다시 로그인한 정보로 이어 썼는지, 키 없이 로그인만 하는 방식에서 내 로그인이 지금 쓰는 공용 앱으로 받은 것인지 그 전 앱으로 받은 것인지, 운영자 서버가 봇 답에 붙는 이름을 알려 주었는지(예·아니오)도 보냅니다. 로그인 정보(토큰)·앱 ID·봇 답에 붙는 이름 자체는 보내지 않습니다. 2.7.0부터는 봇 계정 로그인 방식과 [로그인 상태 유지]·IP 보안을 켰는지, 아인이 [로그인 상태 유지] 칸을 켰는지도 보냅니다(켬·끔 같은 값만). 2.8.0부터는 출석부를 쓴 횟수(체크·체크 풂·빼기·비우기·켜고 끈 횟수, 기능 창 출석부와 OBS 독을 연 것 — 사람 수·닉네임·식별값 없이 횟수만), 신청곡을 켜고 끈 횟수, 익명 후원에 시청자 식별값이 함께 왔는지(예·아니오 — 식별값 자체는 보내지 않음), 치지직 채팅 정보에 어떤 칸이 오는지(칸 이름만, 실행마다 한 번 — 값은 보내지 않음)도 보냅니다. 2.9.0부터는 진단 정보에 운영자 서버가 이용권 동기화 때 내준 확인 표(채널 식별자·만료 시각·서명)를 함께 보냅니다 — 보낸 진단 정보가 그 채널의 것인지 확인하기 위한 것으로, 로그인 정보는 담겨 있지 않습니다. 2.9.0부터는 봇을 켤 때 Windows 판 번호(예: 10.0.26200)와 설정·기능 창을 띄우는 브라우저 종류(Edge·Chrome·기본 브라우저 — 설치 경로는 보내지 않음), 연결 오류의 종류 코드(예: ENOTFOUND — 주소·값 없이), 끊겼다가 다시 붙기까지의 시도 횟수·시간, 아인 창 안내 띠를 보이거나 누른 횟수도 보냅니다. 2.9.0부터는 봇 계정 자리에 넣은 계정이 방송 계정과 같은지(예·아니오만 — 이름·채널 식별자는 보내지 않음)도 보냅니다. 2.9.0부터는 다른 곳(다른 사이트·다른 주소)에서 온 요청을 아인이 거절한 적이 있는지도 실행마다 한 번, 횟수만 보냅니다(주소·머리 값은 보내지 않음). 2.10.1부터는 Microsoft Store 별점 안내 띠를 닫은 횟수와, 띠를 눌러 연 별점 창의 결과 상태(성공·취소·오류 같은 상태 이름만 — 별 수나 쓴 글은 보내지 않음)도 보냅니다. 봇을 켤 때의 Node.js 판과 이용권 상태(체험·이용권), 구독·구독권 선물이 올라왔을 때의 티어·개월·개수(이름·메시지 없이)도 보냅니다. 오류 메시지는 로그인 정보처럼 보이는 값과 긴 값을 지우고 200자까지만 보내지만, 파일 경로(Windows 사용자 폴더 이름 포함)가 들어갈 수 있습니다. 오류의 원인을 찾아 고치고 어떤 기능이 얼마나 쓰이는지 살피는 데 씁니다(5항). 채팅 내용·시청자 닉네임·후원 메시지·API 키·로그인 쿠키·출석 기록·출석부 기록은 포함되지 않습니다. 설정 화면의 [진단 정보 보내기]를 끄면 전송되지 않습니다.
  • 최초 실행 신호 (1.8.0부터): 앱을 처음 실행할 때 이 컴퓨터에서 만든 무작위 설치 식별자와 프로그램 버전, 스토어 설치 여부를 한 번 전송합니다. 설치 뒤 초기 설정을 마치지 못한 이용자가 얼마나 되는지 파악해 설치 과정을 고치기 위한 것으로, 치지직 채널·닉네임·IP 주소는 포함되지 않습니다. 2.1.1부터는 같은 설치 식별자로 초기 설정 진행 단계(어느 화면까지 진행했는지, 막힌 단계의 종류 — 예: 키 형식 오류, 로그인 실패)도 함께 전송합니다. 입력한 API 키·로그인 정보·이름은 포함되지 않습니다. 2.9.0부터는 같은 설치 식별자로 봇을 켰는지와 첫 이용권 동기화가 됐는지(됨·안 됨만)도, 첫 동기화가 될 때까지만 보냅니다. 운영자 서버는 이 신호를 치지직 채널이나 이용권 기록과 잇지 않으며, 받은 때는 시각 없이 날짜로만 둡니다(5항). 설정 화면의 [진단 정보 보내기]를 끄면 그 뒤로는 전송되지 않습니다. 이 설정은 처음에 켜져 있어, 처음 실행할 때의 신호와 초기 설정 중의 진행 단계는 설정을 바꾸기 전에 전송됩니다.

이용권은 이용자의 치지직 채널 식별자를 기준으로 관리됩니다. 운영자가 보관하는 기록과 그 목적·근거·보관 기간은 5항에 있습니다.

3. 제3자 서비스

  • 치지직(네이버): 프로그램은 이용자를 대신해 치지직 공식 API에 연결하여 채팅·후원·구독 정보를 주고받습니다. 이는 이용자가 직접 로그인·동의한 범위 내에서 이루어집니다. 2.3부터는 운영자가 치지직 개발자 센터에 등록한 앱으로 로그인하며, 동의 화면에 요청하는 권한이 표시됩니다(방송 스트림키는 요청하지 않습니다). 요청하는 권한은 채팅 읽기·쓰기·공지, 후원·구독 조회, 채널·방송·채팅 설정, 활동 제한입니다. 지금 쓰는 것은 유저 조회, 채팅 메시지 조회·쓰기(출석·명령어·반복 공지), 후원 조회(후원 감사 인사)이고, 나머지는 앞으로 넣을 기능을 위해 미리 받아 둡니다. 나중에 권한을 늘리면 모든 이용자가 다시 로그인해야 하기 때문입니다. 구독·선물 인사는 채팅에 올라오는 구독 메시지를 보고 동작해 따로 권한이 필요 없습니다. 봇 계정(부계정)을 쓰지 않으면, 봇이 보내는 채팅은 운영자가 이 앱을 등록한 봇 전용 계정의 이름("아인 봇")으로 표시됩니다. 직접 발급한 API 키로 쓰는 경우에는 이용자 본인 계정 이름으로 표시됩니다. 봇 계정(부계정)을 쓰는 경우에는 그 계정으로 채팅을 보내고, 그 계정의 치지직 채널 소개에 "아인으로 만든 봇 · einbot.kr" 한 줄을 넣습니다. 원래 소개 글과 닉네임 등 다른 채널 설정은 바꾸지 않고, 방송 계정의 채널 소개는 건드리지 않습니다. 설정 → 봇 계정에서 끄면 그 한 줄만 지웁니다. (2.2.5) 2.3.1부터는 봇 계정을 새로 연결하면, 그 계정에 프로필 사진이 없을 때 아인 기본 그림 파일을 치지직에 올려 프로필 사진으로 넣습니다. 이미 있는 사진은 바꾸지 않고, 방송 계정의 사진은 건드리지 않습니다. 설정 → 봇 계정에서 끄면 아인이 넣은 그림만 뺍니다. 2.3.0까지 봇 계정을 연결해 쓰던 경우에는 직접 켜야 동작합니다. 2.5.0부터는 팔로우 감사 인사나 팔로우 알림을 켠 경우에 한해, 방송 중에 봇 계정으로 내 채널의 팔로워 목록(닉네임·팔로우한 시각)을 1초마다 읽어 새로 팔로우한 사람을 찾습니다. 이 목록은 이용자가 봇 계정을 내 채널의 채널 관리자로 지정했을 때만 읽힙니다. 읽은 내용은 인사와 알림 카드에만 쓰고 운영자 서버로 보내지 않으며, 두 기능을 끄면 읽지 않습니다.
  • Cloudflare: 운영자 서버(이용권 확인·로그인 중계·진단 정보와 주문 기록 보관)와 설치 파일 내려받기에 쓰입니다. 맡기는 일과 나라 밖으로 옮기는 정보는 7항에 있습니다.
  • (주)스마일서브(iwinv): 주문 확인 서버를 운영하는 데 쓰입니다(한국 서울). 네이버 커머스 API는 등록해 둔 IP에서만 부를 수 있어, 고정 IP가 있는 이 서버가 주문 확인과 발송 처리를 맡습니다. 맡기는 일은 7항에 있습니다.
  • Microsoft Store: 스토어판 아인은 새 버전을 확인하고 설치할 때 Windows의 Microsoft Store 앱 업데이트 기능과 스토어 공개 앱 정보(displaycatalog.mp.microsoft.com)를 이용합니다. 이 과정은 Windows와 Microsoft 계정의 개인정보처리방침을 따르며, 아인이 따로 덧붙여 보내는 정보는 없습니다. (2.2.3) 2.10.1부터는 아인 창의 별점 안내 띠를 누르면 Windows의 Microsoft Store 별점·리뷰 창을 띄우고, 그 창을 띄울 수 없으면 Microsoft Store 앱의 아인 평가 페이지를 엽니다. 별점과 리뷰는 Microsoft Store에 직접 남기는 것이며, 아인은 창이 닫힌 뒤의 결과 상태(성공·취소 같은)만 알고 별 수나 쓴 글은 받지 않습니다.
  • 네이버 커머스(스마트스토어): 주문번호로 결제 여부를 확인하고, 결제된 이용권 주문을 "직접 전달"로 발송 처리할 때 주문 확인 서버가 이용합니다. 네이버에서 받는 구매자 정보는 4항에 있습니다.
  • 네이버 애널리틱스: 이 웹사이트(einbot.kr)의 방문 통계(방문 수·유입 경로)를 보는 데 씁니다. 프로그램(아인) 자체에는 적용되지 않습니다. 쿠키로 모으는 것과 막는 방법은 8항에 있습니다.
  • 웹사이트 einbot.kr — GitHub Pages·jsDelivr: 이 웹사이트는 GitHub Pages에 올려 두었습니다. 웹사이트를 열면 방문자의 IP 주소가 보안을 위해 GitHub에 기록되며, 이는 GitHub의 개인정보처리방침을 따릅니다. 운영자는 이 기록을 받지 않습니다. 웹사이트의 글꼴(Pretendard)은 jsDelivr에서 불러오며, 이때 IP 주소 등 브라우저가 보내는 정보가 jsDelivr에 전달됩니다. 티스토리에 있는 블로그 blog.einbot.kr 에는 티스토리의 개인정보처리방침이 적용됩니다.
  • 문의 창구 — Gmail(Google)·디스코드: 문의 메일은 Gmail 주소 einbot.help@gmail.com 으로, 디스코드 문의는 운영자의 디스코드 문의 서버([질문] 방)로 받습니다. 받는 정보와 보관 기간은 5항, 메일이 나라 밖으로 옮겨지는 것은 7항에 있습니다.
  • 운영자 장부 — Google 스프레드시트: 운영자가 스마트스토어 주문마다의 결제·환불을 적는 장부(세법이 정한 장부)를 두는 곳입니다. 운영자의 Google 계정에서 도는 장부 스크립트(Google Apps Script)가 매일 아침 주문 확인 서버에서 그 사이 바뀐 주문의 매출·환불 줄을 받아 적습니다. 적는 정보는 5항, 나라 밖으로 옮겨지는 것은 7항에 있습니다.
  • 디스코드(discord.com): 디스코드 알림을 켠 경우에만, 방송이 시작될 때 이용자가 넣은 웹훅 주소로 방송 제목·카테고리·방송 링크·방송 시작 시각·썸네일 주소·채널 이름·봇 이름을 보냅니다. 시청자 정보는 보내지 않습니다. (1.9.3)
  • 글꼴 CDN(Google Fonts, jsDelivr, 네이버 hangeul.pstatic.net): 방송 화면 오버레이(기능 창의 미리보기·글꼴 고르기 목록 포함)가 기본 글꼴(Pretendard, jsDelivr)과 채팅 오버레이에서 고른 글꼴을 내려받을 때 연결됩니다. 개인정보는 전송되지 않습니다.
  • TITS(Twitch Integrated Throwing System): 이용자가 TITS 연동을 켠 경우에만, 같은 컴퓨터 안(127.0.0.1)에서 실행 중인 TITS에 아이템 던지기·트리거 실행 요청을 보냅니다. 인터넷으로 나가지 않으며 채팅 내용·닉네임은 보내지 않습니다. TITS와 VTube Studio는 각 개발사의 정책을 따릅니다.
  • 유튜브(YouTube, Google): 이용자가 신청곡을 켠 경우에만 연결됩니다. 신청된 영상의 제목·채널 이름을 확인하려고 유튜브의 공개 oEmbed 주소(youtube.com)에 영상 주소를 보내고, 방송 화면과 플레이어 창에서는 유튜브 공식 플레이어(IFrame Player API)로 영상을 재생하며 썸네일을 i.ytimg.com에서 불러옵니다. 이때 이용자 컴퓨터의 IP 주소 등 브라우저가 보내는 정보가 유튜브에 전달될 수 있고, 이는 유튜브·Google의 개인정보처리방침을 따릅니다. 시청자 닉네임·채팅 내용은 보내지 않습니다. 4. 스마트스토어에서 이용권을 살 때

이용권은 네이버 스마트스토어에서 팝니다. 결제하면 네이버가 판매자인 운영자에게 주문 정보를 넘깁니다. 운영자는 이 정보를 구매자에게서 직접 받지 않고 네이버에서 받습니다.

  • 받는 정보: 주문번호와 주문 내용(상품·옵션·수량·결제 상태 등), 주문한 사람의 아이디·이름·연락처, 받는 사람의 이름·주소·연락처, 배송 메모. 이용권은 보낼 물건이 없지만 이 상품 분류는 배송지를 꼭 받게 되어 있어 배송지도 함께 옵니다. 운영자는 판매자센터에서 결제가 끝난 주문의 이 정보를 볼 수 있습니다.
  • 쓰는 곳과 근거: 결제 확인, 발송 처리, 환불과 문의 처리, 그리고 주문마다의 결제·환불 기록(운영자 장부 — 5항)에만 씁니다. 이용 계약을 지키는 데 필요한 처리이고(개인정보 보호법 제15조 제1항 제4호), 결제·환불 기록은 세법이 정한 장부이기도 합니다(같은 항 제2호 — 6항). 이용권은 보낼 물건이 없어 "직접 전달"로 발송 처리하며, 배송지로 무엇을 보내지는 않습니다.
  • 주문 확인 서버가 받는 것: 주문 확인 서버(한국 서울 — 7항)는 5분마다 새로 결제된 주문을, 주문번호를 등록할 때와 하루 한 번 취소·반품을 다시 볼 때, 그리고 매일 아침 운영자 장부의 장부 스크립트가 물을 때(그 사이 바뀐 주문 — 처음 설치할 때는 2026년 8월 1일부터의 주문 모두) 네이버 커머스 API로 주문 정보를 받습니다. 이때 위 구매자 정보도 함께 오지만, 서버는 상품주문번호·주문 상태·상품명·옵션·수량만 읽고, 장부 줄을 만들 때는 결제일·결제 금액과 결제 수단·할인·수수료·정산 예정 금액·과세 구분·구매확정일·취소·반품 날짜(같은 주문을 묶으려고 주문번호도)를 더 읽습니다. 나머지는 저장하거나 기록하지 않으며 운영자 서버로 보내지 않고, 장부로는 이름·연락처·주문번호·상품주문번호를 뺀 결제·환불 줄(5항)만 보냅니다.
  • 남는 기록: 운영자 서버에는 등록한 주문번호와 그 채널·일수·등록한 때, 취소·반품이면 그 상태 이름이 남고, 주문 확인 서버에는 발송 기록(상품주문번호)이 남습니다(5항). 구매자 이름·연락처·배송지는 운영자의 서버에 남지 않습니다. 운영자의 장부(Google 스프레드시트 — 5항·7항)에는 주문마다 결제일·금액·이용권 종류 같은 결제·환불 기록이 구매자 이름·연락처·주문번호 없이 남습니다.
  • 네이버에 남는 정보: 판매자센터의 주문 정보는 네이버의 시스템에 있으며 네이버의 방침을 따릅니다. 구매가 확정되면 네이버가 구매자 연락처를 지웁니다(직접 전달 주문은 발송하고 4주쯤 지나면 저절로 구매가 확정됩니다). 판매자센터의 구매확정 내역은 최근 2년 안의 주문까지 볼 수 있습니다.
  • 판매자 개인정보처리방침과의 관계: 스마트스토어에 공개한 판매자 개인정보처리방침의 업무 위탁((주)스마일서브)과 국외 이전 "없음"은 네이버에서 받은 구매자 이름·연락처·배송지에 대한 것입니다. 아인에 등록한 주문번호와 그 주문의 취소·반품 여부는 운영자 서버(Cloudflare)에, 이용권·환불 문의 메일은 Gmail(Google)에, 주문마다의 결제·환불 기록(이름·주문번호 없이)은 운영자의 장부(Google 스프레드시트)에 남으며, 이들을 맡기는 곳과 나라 밖으로 옮겨지는 것은 7항에 있습니다.

5. 운영자가 보관하는 정보와 보관 기간

운영자는 개인정보를 처리하면서 따로 동의를 받지 않습니다. 그래서 운영자가 보관하는 정보마다 담긴 것과 쓰는 곳, 개인정보 보호법 제15조 제1항의 근거와 보관 기간을 함께 적습니다. 근거는 세 가지입니다: 계약(제4호 — 이용 계약을 지키거나 계약 전에 요청받은 일을 하는 데 필요함), 법령(제2호 — 법이 남기라고 정함, 6항), 정당한 이익(제6호). 2항에서 저장하지 않고 거쳐 가기만 하는 처리(로그인·갱신 중계와 이용권 동기화 때의 채널 확인)도 계약(제4호)에 따른 처리입니다.

운영자 서버(Cloudflare — 7항)

  • 체험·이용권 기록: 치지직 채널 식별자, 체험을 시작한 때, 이용 기간이 끝나는 때, 그 채널에 등록한 연장 코드 번호·주문번호(최근 100개). 체험을 30일 세고 채널마다 한 번만 주며, 다시 설치해도 남은 기간이 이어지고 같은 번호가 두 번 더해지지 않게 합니다. 근거: 계약. 보관: 체험과 이용 기간이 모두 끝난 날부터 5년(그동안은 같은 채널에 체험을 다시 주지 않습니다).
  • 주문번호·연장 코드 기록: 등록한 주문번호나 연장 코드 번호, 등록한 때, 더한 일수, 등록한 채널 식별자, 취소·반품을 다시 볼 주문번호 목록. 같은 번호를 다시 쓰지 못하게 하고 결제·환불 문의를 확인합니다. 근거: 계약, 스마트스토어 결제에 따른 기록은 법령도(6항). 보관: 등록한 날부터 5년. 운영자가 값을 받지 않고 준 연장 코드(헌정판·시험용)의 기록은 법에 따라 남기는 기록이 아니어서, 지워 달라고 하면 지웁니다(같은 코드를 다시 쓰지 못하게, 누가 썼는지 알 수 없는 "쓴 코드" 표시만 남깁니다).
  • 받아 둔 주문: 주문 확인 서버가 잠시 답하지 않을 때 받은 주문번호, 채널 식별자, 받은 때, 다시 확인한 횟수와 결과. 주문 확인 서버가 돌아오면 저절로 반영하려는 것입니다. 근거: 계약. 보관: 반영되면 곧 지웁니다. 서버가 다시 보다가 30일 안에 확인되지 않거나, 주문이 없거나 취소됐다고(또는 다른 채널이 먼저 등록했다고) 확인되면 받아 두기에서 빼고, 문의에 답할 수 있게 그 까닭과 함께 90일 더 둔 뒤 지웁니다(길어야 약 120일). 이용자가 같은 번호를 다시 넣어 주문이 없거나 취소됐다고 확인된 때는 곧 지웁니다.
  • 취소·반품 기록: 등록한 지 40일이 안 된 주문을 하루 한 번 다시 보아, 취소·반품이면 주문번호, 채널 식별자, 더했던 일수, 등록한 때, 알아챈 때, 주문 상태 이름을 적습니다. 이용 기간은 저절로 줄이지 않습니다(9항). 근거: 계약·법령. 보관: 적은 날부터 5년.
  • 잠금 표시: 같은 주문이 동시에 두 번 반영되지 않게 잠깐 거는 표시입니다. 주문번호 대신 그 번호로 만든 해시값을 이름으로 씁니다. 근거: 계약. 보관: 보통 1초 남짓 뒤 지우고, 남은 것은 하루 한 번 치울 때 지웁니다.
  • 진단 정보(2항): 오류의 원인을 찾아 고치는 데 씁니다. 근거: 계약. 보관: 받은 날부터 30일 뒤 저장소 규칙으로 자동 삭제됩니다.
  • 이용 현황 통계: 운영자는 위 기록의 채널 식별자로 아인을 실제로 쓰는 채널 수와 기능 사용을 세고, 기록이 있는 채널의 치지직 공개 채널 이름·팔로워 수를, 새로 체험을 시작한 채널은 인증 표시·최근 방송 카테고리도 치지직 공개 API로 찾아봅니다. 이용 현황을 알고 프로그램을 고치는 데만 씁니다. 근거: 정당한 이익. 보관: 찾아본 결과는 운영자 서버에 저장하지 않습니다. 운영자 컴퓨터에 만드는 보고 파일에는 채널 이름·식별자를 가려 적고(팔로워 수는 구간으로), 만든 날부터 30일이 지나면 지웁니다.

최초 실행 신호(2항)는 채널과 잇지 않는 설치 통계로 두어 위 목록에 넣지 않았습니다. 운영자 서버는 설치 식별자마다 버전, 스토어판 여부, 초기 설정 진행 단계, 봇을 켰는지와 첫 이용권 동기화가 됐는지(됨·안 됨만), 이들의 횟수, 신호를 받은 날짜(시각 없이)만 두고, 치지직 채널이나 이용권 기록과 잇지 않으며 운영자도 둘을 맞춰 보지 않습니다. 설치 과정을 고치는 데만 쓰고, 마지막으로 신호를 받은 날부터 1년이 지나면 저절로 지워집니다.

9. 자동으로 정해지는 것

  • 취소·반품: 등록한 주문이 나중에 취소·반품되어도 기록만 하고, 이용 기간을 저절로 줄이지 않습니다.

여기에 쓰는 정보는 치지직 채널 식별자, 체험을 시작한 때, 이용 기간이 끝나는 때, 주문의 결제 상태와 상품·수량, 연장 코드에 담긴 일수입니다. 결과가 이상하면 13항의 메일로 설명이나 다시 확인을 요구할 수 있습니다. 운영자가 기록을 직접 보고 30일 안에 답하며, 더 걸리면 그 까닭을 알립니다. 요구를 받아들이지 못하면 10일 안에 그 까닭과 이의를 제기하는 방법을 알립니다.
